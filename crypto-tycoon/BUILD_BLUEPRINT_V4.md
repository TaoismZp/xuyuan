# Crypto Tycoon — Build Blueprint v4 (Controlling Drawing)

## Status
This is the **controlling construction drawing** for the current rebuild under `WISH_DELIVERY_V7.md` **v7.5 Construction-Style Silent Finished Reality**.

It supersedes `BUILD_BLUEPRINT_V3.md` only where this document is more explicit. All system decomposition, Reference-to-Implementation mapping, asset manifest, camera/composition and Stage-1 scope from v3 remain in force.

The accepted build must never import or render `keyart-chunk-*.js`, `visual-v3*`, screenshots, mockups or any Reference Fixture pixels at runtime.

The existing public game remains the fallback until the new candidate passes construction supervision, gameplay acceptance, mobile/performance acceptance and exact-build public delivery acceptance.

---

## 1. Binding Chain
Every supervision report is invalid unless it binds all four identities:
1. **Vision Fixture**: `REFERENCE_FIXTURE.md` + locked effect-image SHA-256.
2. **Controlling Blueprint**: this file path + current Git blob SHA.
3. **Candidate**: exact candidate commit SHA + candidate version marker.
4. **Evidence**: exact workflow run + artifact/screenshots produced from that candidate.

A PASS against an older/easier blueprint is void. A screenshot from a different commit is void.

---

## 2. Production Bottleneck
Current highest-weight bottleneck remains **commercial stylized 3D art reconstruction**.

Quality priority:
1. silhouette / composition
2. authored hero assets and landmark density
3. tile storytelling / readability
4. material hierarchy
5. lighting / contact / depth
6. character collectible quality
7. UI-world cohesion
8. motion / game feel
9. performance
10. gameplay integration
11. deployment

Until items 1–7 pass Stage-1 supervision, gameplay expansion is prohibited.

## 3. Stage-1 Acceptance Blueprint
At the locked desktop evidence viewport (1672×941) and iPad landscape (1194×834), the real-time WebGL candidate must meet every minimum:

| Category | Minimum |
|---|---:|
| Composition | 8.0 |
| Spatial depth | 8.0 |
| Authored forms | 7.5 |
| Material hierarchy | 7.5 |
| Lighting / separation | 7.5 |
| Character quality | 7.5 |
| Landmark density | 8.0 |
| UI-world cohesion | 7.5 |
| Readability | 8.0 |
| Desirability / product class | 8.0 |

Hard FAIL regardless of average if:
- Reference Fixture pixels appear in runtime;
- a hero asset reads first as a placeholder / raw primitive assembly;
- the active scene reads as a webpage/dashboard instead of a 3D tabletop world;
- the board stops dominating the composition;
- the candidate remains materially lower product class than the effect drawing;
- candidate, blueprint and evidence identities do not match;
- Chinese title/tile information is broken on the supervised surface;
- the build needs darkness, bloom, blur or HUD coverage to hide weak authored forms.

## 5. Stage-2 Minimal Interactive Slice
Only after Stage 1 PASS:
- real roll input;
- real dice state/animation;
- human token movement on the same 24-tile loop;
- one asset purchase/pass decision that changes serializable state;
- one bot turn;
- one market-regime transition;
- HUD/state synchronization;
- post-interaction screenshot regression.

Stage-2 PASS requires the interaction to preserve the accepted Stage-1 visual hierarchy. Functional progress cannot pay for visual regression.

## 6. Stage-3 Full Gameplay
Only after Stage 2 PASS:
- integrate the proven 24-tile domain rules;
- buy / rent / upgrade / sector bonus;
