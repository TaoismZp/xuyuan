# Crypto Tycoon — Independent Supervision Protocol

## Role
The Supervisor is not the builder. The Supervisor's job is to detect divergence, shortcuts, fake convergence and delivery mismatch before the user sees a candidate.

The Supervisor may not justify defects with implementation difficulty, code volume, CI success or sunk cost.

## Stop-Work Authority
The Supervisor must stop expansion immediately if any A-class defect appears:

### A1 — Reference substitution
Any Reference Fixture pixel, screenshot, mockup or pre-render is used to impersonate real-time hero scenery.

### A2 — Wrong product class
At equal displayed size, the candidate still reads as developer scene / dashboard while the reference reads as commercial 3D game.

### A3 — Blueprint drift
A hero asset or system is implemented with a materially cheaper method than the Build Blueprint without the blueprint being revised first.

### A4 — Placeholder permanence
Primitive stand-ins, emoji, flat cards, generic boxes or debug visuals remain on a hero surface and are being treated as final.

### A5 — Progress Without Convergence
Two consecutive visual passes add work but do not materially reduce the top visual gap.

### A6 — Delivery mismatch
The public URL, screenshot evidence and accepted commit are not the same build.

## Inspection Rhythm

### Before construction
Check:
- Reference Fixture locked;
- Build Blueprint complete;
- Asset Manifest complete;
- Production Bottleneck identified;
- relevant Skills actually read and recorded;
- forbidden shortcuts explicit.

### After Vertical Slice
Inspect only the reference camera + iPad camera.
Do not reward unseen features.

Score:
1. composition
2. depth
3. authored forms
4. materials
5. lighting
6. characters
7. landmarks/density
8. UI-world cohesion
9. readability
10. desirability/product class

Use the thresholds in `BUILD_BLUEPRINT_V2.md`.

### After interaction integration
Check that dice movement, token movement, modal/actions and bot turns do not collapse the composition into ordinary webpage UI.

### Before deployment
Check:
- no runtime import of `keyart-chunk-*.js`;
- no reference image/background substitution;
- candidate screenshots tied to candidate SHA;
- desktop and iPad target views captured;
- no A-class issue open.

### After deployment
Open the exact public candidate URL and verify:
- correct commit/build;
- intro;
- active play;
- roll/move;
- one economic action;
- bot turn;
- replay/end path as applicable;
- tablet layout.

## Evidence Required
Each supervised pass must record:
- candidate commit SHA;
- screenshot filenames / artifacts;
- target viewport;
- 10-category score;
- A/B/C defects;
- PASS/FAIL;
- explicit top remaining gap.

## Severity
- **A**: blocks further expansion or Final.
- **B**: significant quality defect; must close before Final.
- **C**: polish issue; may remain only if it does not violate original promise.

## Final Acceptance
The Supervisor signs PASS only if:
- all A issues closed;
- no unresolved B issue breaks the promised effect;
- active-play screenshot passes equal-size reference comparison;
- runtime does not consume Reference Fixture pixels;
- functional core loop works;
- real public GitHub Pages surface matches accepted candidate;
- iPad landscape remains the same game world.

Without this PASS, the builder is not allowed to replace the public root or tell the user the game is finished.
