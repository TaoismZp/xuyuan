# 「断档重生」操作协议 v1（公开的通用方法，不含私人项目数据）

**主目录**：ChatGPT 私密文件库 `/跨对话恢复中心/README.md`。**生效规范**：每次读取 GitHub `wish-delivery/CURRENT.json`，不从此文推断当前版本。

## 用法

用户在任何可回复的对话输入：

> 断档重生

也可输入「断档重生：个人网站」指定目标。**四个字是触发器，不是备份**。要让它在全新聊天中自动生效，账号须安装 `/跨对话恢复中心/CUSTOM_INSTRUCTIONS.txt` 中的全局自定义指令；本仓库提交不等于用户账号已安装。

## 首要动作为实际读取

1. 解析目标。明确项目/讨论名称优先；否则取当前对话中最后明确、未闭合的工作主题；全新或不确定时读取私密注册表与有权限的来源。若候选超过一个且无决定性证据，列出候选让用户**只选择名字**，不猜。
2. 读取对应项目 `RECOVERY` / `PROJECT_STATE` / 原稿或主题检查点；并通过具体文件、Git commit、验收运行、网页/内容证明当前事实。**新对话必须自行重新读取，而非照抄旧聊天。**
3. 区分 PASS、PENDING、UNVERIFIED 和 FAIL；确认用户原始目标、已锁定决策、产物、不可逆动作和可执行下一步。
4. 未完成且安全的动作直接执行；必须本人身份/发布/授权的步骤只在用户当前确认后执行；明确终止的项目不自动重启。
5. 新阶段结果保存适当权限的恢复档案（不覆盖原稿），回读确认；无法保存就输出交接卡并写「尚未归档」。

## 恢复结果输出最小形式

「识别为：…；恢复至：…；已验证：…；当前阻塞：…；立即执行的下一步：…」。

不要只汇报状态就停止；能继续则继续，不能继续说明唯一真正障碍。不要拿 CI PASS 冒充真实用户验收。

## 歧义与隐私

- 全新聊天裸「断档重生」+ 多个未完项目：仅让用户选择名字，不能假设最新时间=最相关。
- 裸短语 + 单一唯一且已索引项目：可进入 **核验阶段**，但索引的「存在」不是交付 PASS。
- 未索引主题：检索 Library、授权连接器和真实文件，不直接宣布丢失；找到后补索引。
- 档案失效或版本冲突：停止自动写入，核对原始来源，标记 UNVERIFIED。
- 不把完整私密聊天或未发表稿件放在公开 `TaoismZp/xuyuan`。
- **逐字历史**：此机制只能接替已记录的工作状态；旧聊天本身需要 ChatGPT 数据导出，无法在这里保证完整恢复。

## Reality Gate

本仓库的 `revival-router.mjs` 是纯数据的决策示范，能够检查分流规则，**没有读取 ChatGPT 账号任意对话的权限**。CI 使用合成数据，仅能证明不乱猜，不是跨会话冷启动 PASS。

跨会话真实冷启动：**PENDING**；账号级自定义指令实际启用：**UNVERIFIED**（不能远程代替用户设置）。
