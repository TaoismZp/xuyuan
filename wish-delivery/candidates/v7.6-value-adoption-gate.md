# 《许愿式交付》v7.6 候选补丁：价值与长期使用 Gate

状态：**CANDIDATE / NOT ADOPTED**，不覆盖 `wish-delivery/versions/v7.5.md`；提案日期：2026-11-04。

## 改动的真正目的
v7.5 能确保按选定 Vision / Blueprint 施工、独立监理、交付表面验收和身份链绑定。但它不能单凭工程 PASS 证明「目标值得做」「目标用户愿意持续用」「这一流程的总成本合理」。

### 拟新增 Gate 0：Problem / No-Build Comparator
复杂项目开始前，写出：
- 用户想完成的真实任务（Job-to-be-Done）和实际主交付物，区分“我想要的网站”与“发文/被读/留存文章”的结果；
- 不构建新产品的替代方案及其操作成本；若替代方案已足够，先不新增复杂系统；
- 最大反证假设、一个最便宜且可逆的验证动作和判定结果（PASS / FAIL / UNVERIFIED）；
- 用户掌握的不可替代决策权、隐私及不可逆风险。

Gate 0 不要求空泛市场研究、固定问卷或冗长 PRD；已明确且成本低的需求可写 5 行。**不是以文件数量为目标。**

### 拟新增 Gate 7：Adoption / Ownership Reality
正式交付后，保留真实使用 Gate：本人是否无技术协助完成核心闭环、出现哪些实际摩擦、内容资产是否可导出/迁移、日常维护成本、失效时如何恢复。闭环未由本人执行，不得写“站长已验证”。

### 拟增加成比例执行与止损
- 短、可逆工作：小型任务契约 + 直接验收，不机械索要四件套；
- 长期/复杂/视觉敏感项目：保留 v7.5 全部身份链和四件套；
- 两次同方向修补仍无法降低用户真实操作阻力，停止增加 UI 或文档，先比较 GitHub 原生编辑、token-free writer、受限 CMS 三条替代路径；
- 无依据不得自造转化率、收益率、节省工时或满意度数字。

## 为什么这是候选而非 v7.5 正式升级
当前证据只覆盖一个网站工作流及旧项目审视材料，还没有新会话盲接班、跨项目代表性试验、作者真实发布。若该 Gate 造成文档开销或妨碍实际交付，应撤回或删减。

## 原 v7.5 保留的强约束
Vision/Blueprint 身份链、独立监理、same-surface 验收、原稿不覆盖、未验收不得 FINAL、公开仓库禁止私人材料全部保留。

## 下一验证
1. 网站站长实地走完一篇真实文章：已有原稿 → 写作页复制 → GitHub Commit → Pages → iPad 阅读。
2. 记录每次需要站长手动解释/重复/重试的环节，不臆造指标。
3. 从全新对话无历史进入 RECOVERY.md，以真实代码变更而非复述档案证明恢复价值。
