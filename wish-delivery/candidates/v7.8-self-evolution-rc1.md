# 许愿式交付 · 自我迭代候选 v7.8-RC1

**状态：CANDIDATE / NOT ACTIVE（2026-11-04）**  
生效规范仍由 [CURRENT.json](../CURRENT.json) 唯一确定，目前是 v7.6。版本号 v7.7 已被其他草案占用，不得复用；此候选不覆盖 v7.5、v7.6、v7.7 或先前“v7.6 价值补丁”。后续版本号能否晋级另行判定。

## 一、继承与目标

无条件继承已生效 v7.6 的效果图→施工图→受控施工→独立监理→验收→交付、身份链、Skill 真实性、同表面验证、长期任务恢复、真实交付与监理复杂度上限。不能通过新版本取消旧版本的硬门槛。

**新增的不是更多文档，而是避免做错事情、做假验收和自我证明。**

新协议要同时回答：
1. **值得做吗？** 真正的用户工作是什么；构建与不构建的更轻基线是什么。
2. **做到了吗？** 交付物的核心闭环在用户实际使用表面是否通过。
3. **用下去了吗？** 用户是否掌握持续使用、修改、撤回和迁移能力。
4. **协议怎么证明自己有效？** 采用旧规范作冻结裁判、盲样本和反证测试；候选不能凭自写的绿灯升级自己。

## 二、Gate 0 · Outcome & Alternative Reality（新）

对**复杂、长期或不可逆**任务，在生产前用最短事实记录定义：
- **Job**：用户最终想做成哪件事，而不是助手容易生产哪种文档。
- **Primary Artifact + Delivery Surface**：用户实际拿到什么、在哪里打开/运行/阅读、体验上限是什么。
- **Existing/No-Build Baseline**：不造、复用现成工具、轻量自建至少一个可信对照；明确基线的实际摩擦和局限。用户明确要自建时，不得借“有替代品”擅自否决愿望。
- **Disconfirming Test**：哪个最小真实动作可推翻“这条路线值得做”，并给出成本/可逆性。
- **Rights/Irreversibility**：私密内容、真实发布、付款、授权、不可撤销动作由谁控制。

**比例原则**：短答、已明确的低风险微任务直接执行，不强加四件套、竞品研究或无效追问；复杂项目仍需 v7.6 全部四件套。不要为证明按流程而推迟可直接生产的成品。

## 三、Gate 6.5 · User Outcome Before Proxy Evidence（新）

任何验收声明都需标明 **claim → object identity → evidence → actual verifier → limits**。

必须独立区分：
- 工具可访问、构建成功、截图正常；
- 子系统/功能闭环成功；
- 真实用户的核心闭环成功；
- 交付物可回退、可迁移、可维护。

GitHub CI PASS、Markdown 文件存在、截图很像，都不能晋升为“用户真的能发表长文”“作者真的读完书稿”“游戏好玩”。必要的用户登录/发表/同意未发生：标记 **READY_FOR_OWNER_ACTION / PENDING_OWNER**，不能 FINAL。未能读取的原稿、Skill、聊天历史不得伪称已读取。

**No False Blocking**：子系统成功应以绑定范围的 **SHIPPED_SCOPE** 记录，不因另一个 Gate 待验收而抹掉已证实的成果；但也不得把 SHIPPED_SCOPE 描述为总目标完成。

## 四、Gate 7 · Aftercare & Adoption（新，交付之后）

一旦核心产品交付通过，另起独立的长期使用记录，不以尚未观察到长期行为为借口无限阻止首发：
- 第一次真实独立使用；
- 下一次使用/修改/回滚；
- 内容或数据可导出与迁移；
- 隐私权限、运营成本、故障恢复；
- 用户真实摩擦能否改变下一版路线。

区分 **DELIVERED** 与 **ADOPTED**：前者是即时交付验收，后者需要后续使用证据；不得凭“可能会用”标记 ADOPTED。产品无需为了满足某个未经用户需求的留存 KPI 增加功能。

## 五、Recursive Integrity Gate · 只用于迭代本协议（新）

**Self-Referential Stop Rule**：协议不能使用“执行新协议得出的报告”作为“新协议正确”的唯一证据。必须在候选施工前冻结独立裁判，禁止自证循环。

每次实质自我升级须完成：

1. **冻结旧版**：唯一 CURRENT 指针、旧版规范文件 blob SHA、已锁定规则与真实失败案例；旧规范做否决裁判，新规范不能改裁判。
2. **效果目标**：只写本次用户能感知的增益及不应牺牲的旧能力。将需要验证的条件事先声明。
3. **受控候选**：保留原稿与旧版，给出最小修改；协议文本与执行样例/测试须独立存在，不允许“写新规则即升级”。
4. **反事实/对照**：至少两个异质代表案例和一个故意错误的对抗样本；观察判定或下一动作是否**实际发生变化**，并检查是否引入额外流程负担。合成样本只证明逻辑一致性，不能冒充真人体验结果。
5. **异质监理**：代码/规则的机械校验与**不由生产者单独决定的**用户或另一个独立审核者的质量裁判分开。仅同一个助手复读两套角色，最多叫自审，不能叫独立验收。
6. **晋级权限**：独立检查通过、旧规范硬门槛未丢、真实代表任务验证、用户授权升级、仓库新不可变版本文件+CHANGELOG+CURRENT 原子化提交，缺一只能为 RC/CANDIDATE。
7. **恢复与止损**：若新机制比产品更复杂、两轮没有可观察增益、或者恢复实验失败，保留旧 ACTIVE，候选标 FAIL/REWORK。聊天结束仅做检查点，不是后台自动持续执行。

**一条特别禁止**：不允许把“不经本人的新聊天冷启动验证”写成跨对话恢复 PASS；旧对话无法导出的完整逐字历史也不得由项目摘要替代。

## 六、角色与状态字典

- **DIRECT**：已明确、可逆的微任务直接解决。
- **DISCOVERY_REQUIRED**：复杂任务缺目标或可对照基线，先做最小可逆验证。
- **CANDIDATE**：成品或证据不足，仅候选。
- **FAIL**：隐私、身份链或核心硬 Gate 失败，必须修复。
- **READY_FOR_OWNER_ACTION**：缺用户独有授权/真人操作，不能伪造。
- **SHIPPED_SCOPE**：明确范围内可核验的交付已过，但大目标尚未闭合。
- **DELIVERED**：本次真实核心闭环已验收。
- **ADOPTED**：随后真实使用/修改/恢复再验收通过。
- **BLOCKED_CONTEXT**：缺少可信外部状态或原始材料，不可编造。

候选提供 [决策演练工具](../self-evolution/2026-11-04/decision-engine.mjs)，这是**边界检查器**而不是代替人类的项目经理；其输出不能独立证明满足交付协议。

## 七、本次升级必须通过的否决测试

| 样本 | 必须得到的结论 |
| --- | --- |
| 网站 GitHub Pages 上线但主人从未发文 | READY_FOR_OWNER_ACTION；阅读端可局部 SHIPPED_SCOPE |
| 假 3D 游戏截图可看但不能真玩 | CANDIDATE，不是完成游戏 |
| 复杂工程没有明确用户目标/替代基线 | DISCOVERY_REQUIRED |
| 短、可逆的简单任务 | DIRECT；不强制工程四件套 |
| 私人草稿放进公开仓库仅设 draft | FAIL |
| 旧视觉参考给新版本签名 | FAIL |
| 新对话没有可用档案却假称恢复 | BLOCKED_CONTEXT |
| 已经核验发表、但尚无后续使用证据 | DELIVERED，不能冒充 ADOPTED |
| 协议自改且只靠自身测试宣布生效 | CANDIDATE，不晋级 |
| 长任务只有状态报告无下一动作 | FAIL/INTERRUPTED，不是假完成 |

这些是**合成的防回归案例**，与真实用户测试严格分列。
