# 许愿式交付 v7.2 — Compound Quality Reset

## 触发事故
FIN·TYPE 已经满足“可打开、可运行、完整闭环、真实入口可访问”，但用户同时否定两个一级质量维度：**美工不行、题目也不行**。

这证明 v7.1 以前的系统仍可能出现一种假完成：技术与交付全部通过，但核心内容质量和审美质量同时不达标。

## 根因
1. **Delivery Success 被错误放大为 Product Success**：真实入口可用并不能证明产品值得用。
2. **Content Evaluator 缺位**：题目只验证“能计分、能到 16 型”，没有验证题目是否真实、锋利、难以迎合、能区分不同决策结构。
3. **Design Evaluator 仍不够独立**：即使做了视觉参考和截图 QA，仍可能只验证“整洁/可读/不模板”，而没有验证“审美真的好、品牌成立、愿意继续玩”。
4. **单项 Gate 之间缺少否决权**：功能、部署、视觉、题目没有真正独立的一票否决机制。

## 新增：Compound Quality Failure Protocol
当用户同时否定两个或以上一级质量维度（如内容 + 美工、玩法 + 结果、作者性 + 结构）时，禁止进入局部修补。

必须：
1. 冻结当前版本为失败样本；
2. 将内部 PASS 判定标记为 Evaluator Failure；
3. 回退到 Pre-Production / Contract Compilation；
4. 重新定义各一级质量维度及其独立验收标准；
5. 重新做 Capability Gap Analysis 和 Skill/方法采购；
6. 先做小样 head-to-head benchmark，再决定生产路线；
7. 只有所有一级维度分别过 Gate，才允许重新进入 Final Candidate。

## 一级质量维度必须独立否决
对于交互产品，至少拆为：
- **Core Content Quality**：内容本身值不值得；
- **Interaction/Game Quality**：过程是否有张力、反馈和复玩性；
- **Visual/Brand Quality**：是否好看、可信、独特、克制；
- **Result/Insight Quality**：结果是否像用户、是否有信息增量；
- **Delivery Reality**：用户真实入口是否可用。

任何一项 FAIL，整体不得 Final。不得用“功能很完整”补偿“题目很差”，也不得用“美工很漂亮”补偿“结果很空”。

## 新增：Question Quality Contract（题目质量契约）
金融人格/决策测试的题目不得只满足“可计分”。正式题库必须同时通过：

1. **Domain-native**：问题必须来自真实金融决策冲突，而不是把一般人格题换成金融名词。
2. **No obvious virtue**：每个选项都必须有合理性与代价，不能让用户一眼看出“正确答案”。
3. **Low social-desirability bias**：不能让用户轻易选择“我想成为的人”，而应迫使其暴露真实取舍。
4. **Construct purity**：单题主要测一个核心维度，避免一题同时混进风险偏好、时间偏好、知识水平和道德判断。
5. **Trade-off pressure**：必须存在资源、时间、赔率、不可逆性、机会成本或信息不完整等真实约束。
6. **Coverage**：同一维度不能反复换皮问同一个问题；要覆盖不同市场状态和决策情境。
7. **Discrimination**：不同决策风格的人应有合理分歧，不应大量集中到同一选项。
8. **Adversarial review**：由独立评审尝试找出诱导、语义偏置、重复、伪两难、知识题化等问题。
9. **Behavior-first**：优先问“在这个情境你会怎么做”，而不是“你认为自己是什么样的人”。
10. **Not a fake psychometric claim**：未经过正式心理测量验证前，产品只能定位为“金融决策人格实验/模拟器”，不能冒充科学诊断。

## 新增：Visual Quality Contract（视觉质量契约）
1. 先建立 3–5 个真实成熟产品参考，不以 AI 自己生成的候选互相比较作为唯一 benchmark；
2. 至少产生 3 个**真正不同**的视觉方向，而不是同一套布局换颜色；
3. 视觉评审至少包含：brand fit、desirability、credibility、hierarchy、interaction clarity、mobile polish、distinctiveness、restraint；
4. 生产者不得成为唯一裁判；
5. “不模板”“暗色”“金融感”都不是质量本身；
6. 视觉必须服务产品机制和情绪，不得只做表面皮肤。

## 新增：Pre-Build Benchmark Gate
对于高主观质量任务，禁止直接做完整版。

先选 3–5 个代表性片段做对照：
- 题目：至少 12–20 道候选，来自多个能力来源，盲评后只保留最强题型；
- 视觉：首页 / 核心交互页 / 结果页各做多个方向，先比较再扩展；
- 结果：至少比较 3 种结果叙事结构，看哪一种最有“像我 + 信息增量 + 分享欲”。

只有局部 benchmark 明显胜过旧版，才允许扩大到完整产品。

## 用户整体否定的解释规则
用户说“美工不行”“题目不行”“不好玩”“结果不像我”等，不得自动解释为偏好差异或局部修改意见。

若对应一级质量维度此前曾被内部判 PASS，则默认先判定为 **Evaluator Failure**，先修评价器，再修作品。

## Silent Execution 保持不变
上述重做全过程仍属于内部施工。除账号授权、核心价值冲突或穷尽路径仍无法继续外，不向用户汇报 Skill、候选、测试、Gate、截图或下一阶段。

最终只交付：真实可用且所有一级质量维度均通过的成品。
