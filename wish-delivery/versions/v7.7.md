# 许愿式交付 v7.7 — Benchmark-Parity & Experience Reality

v7.7 继承 v7.6 的全部规则，并修复一个在“币圈大富翁”项目中暴露出的重大缺口：**Functional / Visual / Delivery PASS 仍可能只得到一个技术原型，而不是市场意义上的成熟成品。**

## 1. Market Benchmark Gate（新增硬 Gate）
当目标属于已有成熟产品类别（游戏、App、SaaS、消费产品等），进入施工前必须先建立 3–7 个真实市场参考对象，且不能只看截图。

每个参考对象至少拆：
- Core Loop / 核心循环
- Interaction Grammar / 操作反馈语法
- Motion Language / 动画语言
- Sound & Haptics / 声音与触觉
- Camera / Transition / 镜头与转场
- Reward / Failure Feedback / 正负反馈
- Content Density / 内容密度
- UI State Choreography / 界面状态编排
- Onboarding / Session Rhythm / 上手与单局节奏
- Meta / Live Ops / 长线循环（如目标需要）

### Benchmark Non-Copy Rule
参考是为了提取机制、节奏、质量阈值和设计语法，不复制受版权保护的美术、音频、角色、文案、关卡或其他表达。

### No Category Reinvention Rule
市场上已有成熟答案而团队完全没有做竞品拆解，直接凭想象施工，判 Blueprint FAIL。

---

## 2. Experience Reality Gate（新增硬 Gate）
对交互式 Artifact，Acceptance 不再只检查“能不能完成任务”，必须检查“完成任务的全过程是否达到目标产品等级”。

至少独立验收：
1. **Input Feel**：按下、拖动、选择是否有即时反馈；
2. **Motion Feel**：对象是否有 anticipation / acceleration / impact / settle，而非线性位移；
3. **Audio Feel**：操作、移动、命中、奖励、失败、环境、音乐是否形成分层反馈；
4. **State Choreography**：状态变化是否通过动画/声音/层级被用户感知，而不是只改数字；
5. **Reward Salience**：正反馈是否足够被感知；
6. **Failure Salience**：负反馈是否清晰但不过度惩罚；
7. **Session Rhythm**：等待、行动、结果、下一次行动之间是否有节奏；
8. **Character / World Reactivity**：世界是否会对玩家行为作出可见/可听反应；
9. **Transition Quality**：Modal、页面、场景切换是否像产品而不是调试工具；
10. **Accessibility Controls**：声音开关、Reduced Motion 等必要控制是否存在。

任一核心闭环只有逻辑状态变化而没有足够的感知反馈，Experience Reality = FAIL。

---

## 3. Game Feel Gate（游戏项目强制）
游戏项目必须在 Full Production 前制作一条完整的 **Feel Vertical Slice**。它至少覆盖：

**Input → Anticipation → Action → Motion → Impact → Resolution → Reward/Failure → Recovery → Next Action**

例如骰子棋类：
**按下掷骰子 → 按钮压感/音效 → 骰子预备动作 → 滚动/碰撞声 → 数字锁定 → 棋子逐格移动 → 每格脚步/跳点 → 落地压缩/镜头反馈 → 地块/事件演出 → 金钱/资产变化反馈 → 音乐/环境恢复 → 下一次可操作。**

### No Silent State Change
以下默认不得只用数字/文字更新完成：购买、升级、扣费、奖励、爆仓、市场切换、重大事件、回合开始、胜负结算。

### Audio Is Product Rule
声音不是“最后补几个 mp3”。Audio 必须进入 Asset Manifest、施工图、性能预算和验收：
- UI SFX
- Dice / movement / physical SFX
- Positive / negative stingers
- Event motifs
- Ambience / music
- Mix / ducking / mute control
- Mobile autoplay / resume behavior

### Motion Is Product Rule
动画不是 CSS 装饰。关键交互必须定义：时长、easing、anticipation、overshoot、impact、settle、interruptibility 和 reduced-motion fallback。

---

## 4. Comparative Experience Gate（新增）
“像不像成品”必须对真实市场参考进行同任务对比，而不是只和自己上一版比。

至少对比 5 个高频任务：
- 首次进入
- 第一次核心操作
- 一次正反馈
- 一次负反馈
- 一次状态/场景转移

如果候选的反馈密度、演出层级、声音完整度或节奏明显低一个产品等级，即使功能全绿，也不得 Final。

---

## 5. Final Candidate Rule 补充
在 v7.6 的 Final Candidate Rule 之外，交互式/游戏项目还必须满足：
- Market Benchmark Gate PASS；
- Experience Reality Gate PASS；
- Game Feel Vertical Slice PASS；
- Audio / Motion 已进入真实生产资产而非占位；
- Comparative Experience 不低一个完整产品等级；
- 用户高频 30–60 秒真实操作中，没有“技术 Demo 感”的主要断点。

否则只能称 Prototype / Alpha / Candidate，不得称成熟成品。
