# 许愿式交付 v7.3 — Reference Reality & Skill Proof

## 触发事故
币圈大富翁在“可运行、可玩、已有 3D 视觉效果”的条件下仍被用户判定与目标效果图“天壤之别”。同时复盘发现：仓库虽有 Capability Selection Record，但实际施工没有完整执行“公开搜索 Skill → 读 Skill → 比较候选 → 代表性实测 → 采用并按其方法施工”，形成了新的假完成。

## 根因
1. **没有把效果图升级为正式验收对象**：效果图只是灵感，而不是版本化的 Comparative Quality Fixture。
2. **视觉目标没有反向约束技术路线**：目标是商业级 3D 游戏，却继续沿用 DOM/CSS 倾斜棋盘，技术表面先天无法逼近目标。
3. **Skill Record 替代 Skill Use**：记录了方法名，但没有证明 Skill 被真实读取、筛选、应用并影响实现。
4. **Reference-first 仍停留在原则层**：没有“先做可视目标→锁定→再生产→同视角比较”的硬流程。

## 新增一：Reference Artifact Contract
对于高主观质量、强视觉、强体验或难以仅靠文字规格定义的任务，若用户未给出足够具体的参考物，系统应优先产生一个或多个**可被感知的目标 Artifact**，例如：
- 游戏 / App：关键画面效果图、交互原型、动效样片；
- 设计：关键屏幕 mockup；
- 视频：关键帧 / 分镜样片；
- 文稿：代表性章节 / 段落样稿。

一旦该 Artifact 被用户明确认可或被双方实际作为目标使用，它必须升级为正式 **Reference Fixture**，而不是一次性素材。

Reference Fixture 必须记录：
- 原始文件或稳定可恢复引用；
- 目标表面与目标设备；
- 视觉/体验中哪些特征是必须逼近的；
- 哪些只是灵感、不要求逐像素复制；
- 对比时采用的视角、尺寸、关键状态。

## 新增二：Reference-to-Architecture Gate
在高保真任务中，技术路线必须能解释“为什么它足以达到 Reference Fixture”。

若参考目标包含真实 3D 体积、镜头、光照、材质、角色、空间动画，则：
- CSS perspective / DOM card tilt 不能被视为等价 3D 路线；
- 必须选择 WebGL / Three.js / R3F / Babylon / Unity / Unreal 等真正能承载目标表面的方案之一；
- 若降级为伪 3D，必须有明确约束理由，且不得宣称达到原目标。

## 新增三：Skill Proof Gate
Skill/方法采购从“写了名字”升级为“可追溯证据”。复杂成熟任务必须保留最小 Skill Provenance：
1. 搜索过哪些候选；
2. 实际读取了哪些 Skill / 方法文件；
3. 每个候选解决什么缺口；
4. 为什么采用/淘汰；
5. 哪一条 Skill 规则真实改变了架构、实现或 QA；
6. 代表性子任务是否优于无 Skill 基线或旧路线。

禁止：
- README / star / 名气即采用；
- 只把 Skill 名称写进 BUILD_NOTES 就算“使用”；
- Skill 与实际代码路线无因果关系；
- 未读取 Skill 内容却声称使用。

## 新增四：Minimum High-Gain Capability Stack
不得为了“用了很多 Skill”而堆叠。流程固定为：
**Capability Gap → Candidate Search → Static Review → Representative Spike → Head-to-Head → Minimum Stack Lock**。

最终能力栈只保留能显著提高一级质量维度的 Skill。重复覆盖、只增加流程复杂度、无法在交付表面体现增益的候选应淘汰。

## 新增五：Visual Reality Regression
存在 Reference Fixture 的视觉产品，Final Candidate 前必须做同表面对比：
- 同一目标设备或等效 viewport；
- 同一关键游戏状态/页面状态；
- 至少一张实机截图与 Reference Fixture 并排；
- 逐项检查 silhouette / depth / material / lighting / density / hierarchy / character / UI-world cohesion / mobile readability / desirability。

如果缩小到相同尺寸后仍明显像“两个时代的产品”，Comparative Quality 自动 FAIL。

## 新增六：Placeholder Honesty
以下可用于原型，但不能冒充高保真成品：
- emoji 代替角色/地标；
- 未加工基础几何体充当 hero asset；
- 纯 glow / fog / gradient 充当高级美术；
- CSS 倾斜充当真实 3D；
- 通用 dashboard 卡片充当游戏 HUD。

只要 Reference Fixture 明确要求更高层级，这些必须在 Final 前被真实资产/作者化表面替代。

## 币圈大富翁永久回归样本
旧 3D 版作为失败样本保留：
- Functional Reality：部分 PASS；
- Visual/Brand Quality：FAIL；
- Comparative Quality：FAIL；
- Evaluator：FAIL（曾错误宣布“和效果图差不多”）。

以后任何“高保真 / 3D / 像效果图”的游戏任务，都必须对该事故做回归检查。

## Silent Execution 保持不变
Reference Fixture、Skill Provenance、benchmark、截图对比、评分默认属于内部施工档案，不要求用户充当流程时钟。最终只交付经过同表面验证、与目标 Artifact 真正同层级的成品。
