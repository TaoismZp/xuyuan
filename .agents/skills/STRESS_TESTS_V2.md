## 测什么

比较同一个 AI、相同用户提示、相同取样参数、各自独立的三个条件：

- **A 无 Skill**：只给用户问题，不给 GitHub Skill 文字。
- **B GitHub 精简版 v1.0**：加载 `elite-thinking/SKILL.md` 及 `MODEL_ROUTER.md` 的 **v1.0 Git 提交**（本项目于 2026-11-04 创建的旧版），不提供 v1.1 十大领域路由。
- **C 扩展路由 v1.1**：加载 `elite-thinking/SKILL.md`、`MODEL_ROUTER.md` 与 `DOMAIN_ROUTER.md` 的同一已验证最新提交。不要在 C 组偷加私有原稿。

另对苏格拉底单独测试：无 Skill / GitHub 重建版 `socratic-review/SKILL.md`；因原版未读，暂不能做原版等价判断。

**严禁**：让被测 AI 先读本测试文件；它应该只看到题目和指定 Skill。不要把“使用了模型名称”当成功。各条件要开新会话、清除旧答案与上下文，顺序随机，保留模型/版本/温度/任务/实际读取证据与原始输出。三个条件都不能被评分者提前识别；评分后揭盲。外部 Agent 发现 Skill 的实际证据与直接贴全文的“提示词模拟”分开记录。

## 评分协议

每份盲评输出在以下五个维度各评 0/1：
1. **保留用户真实目标**：没有擅自改写成模型擅长的题目。
2. **选对主要机制**：能解释该领域的关键变量/激励/反馈，而不只是贴名词。
3. **有诊断性反证**：真的能推翻当前判断，而不是形式性的“也可能有风险”。
4. **行动可验证**：有实际执行步骤、观察量及继续/停止条件。
5. **避免确定性幻觉**：区分事实与推断，未假装掌握未给数据/权限。

每题 0–5 分；另记录**致命失败**（例如擅自替用户决定价值目标、以模拟当真实完成、虚构原始模型、编造事实）；致命失败即使 4/5 分仍 FAIL。评分附带原始证据片段和具体原因，不用“看起来更专业”打分。

## 对照结果的正确解释

- C > B：只支持“十领域路由在所测题目/模型环境中有增量”，**不证明**等价于原始 100 工具。
- B/C > A：只支持在所测任务与当前模型上的增量，不可外推所有 AI。
- C ≤ B：先检查路由多样性是否引发误触发、冗长或错误模型；不要因为投入了工作量就判赢。
- 三者都好：可能是基座模型已经掌握该知识，不能声称 Skill 一定有价值；应继续找真正能区分的困难题。
- 原始文件不可完整读取：只能声明与已读摘录的差异、公开文件的覆盖；不得输出“100模型迁移验收通过”。
