# 深写｜DeepWrite

**一次提出目标，内部多轮推演，交付完整成稿。**

DeepWrite 是可恢复、版本化的长篇非虚构写作工作台，源于一次20章写作项目中从早期批量低质、写作路径依赖、跨章漂移，到独立概念图、单章内循环、整书核验的实际协作经验。

**入口**：[START_HERE.md](START_HERE.md) · [当前能力状态](CURRENT.json) · [v0.1方法规范](versions/v0.1.md) · [形成过程](HISTORY.md) · [项目立项](PROJECT_INIT.md) · [盲测方案](EVALUATION.md) · [隐私边界](SECURITY.md)

**质量迭代候选**：[v0.2](candidates/v0.2.md) · [可执行编辑循环](candidates/EDITORIAL_LOOP.md) · [本体迭代检查点](iterations/2026-11-09-quality/RECOVERY.md)。候选针对强制造新发现、商业题材偏置、来源与论断脱节、作者声音和小样评测；仅用于显式选择的开发试验，当前生效版本仍为 v0.1，质量提升尚未获独立盲评证明。

## 现在可以怎样用

在具有 GitHub 读取能力的 ChatGPT/Codex 新对话发送：

> 启动深写：我要写一本【主题】的书，给【读者】读。请读取 https://github.com/TaoismZp/xuyuan/blob/main/deepwrite/START_HERE.md 和 CURRENT.json；先立项及确认可写入的私有档案，研究→完整写作→反驳返工→事实核验→跨章连读→序言尾声→整书成品，不把大纲冒充完成。每个可验证阶段保存状态与唯一下一步；如果能力缺口，明确说明并尽可能完成本回合可做的工作。

中断后：

> 断档重生：深写／【项目名】。从项目 RECOVERY 和真实已保存稿件接班，不从记忆猜。

注意：**上面是任务指令，不等于系统已具备无人值守、一次调用生成整本书的产品能力**。必须按 [CURRENT.json](CURRENT.json) 中的能力状态披露真实完成情况。任何聊天结束后自动后台继续工作，只有真实的自动化/长任务执行器才可以承诺。

## 核心原则

1. **One request ≠ one pass**：用户一次提出需求，系统内部可以多次研究、推翻、返工，但质量门不得跳过。
2. **先研究原生机制**：原始概念图≠章节目录；不能让作者既有母题预先决定新发现。
3. **一章一项不可替代的能力**：写不出独立机制，则删/合并/重研，而不是凑篇数。
4. **后半必须有新发现**：检查新变量、反例、行动约束，而不是重复口号。
5. **跨章与整书审查**：数学正确/单篇不错≠整书可读。
6. **真实成品与身份链**：原稿不覆盖，候选/审稿/来源/版本/SHA绑定。未通过真实人类审阅不假称通过。
7. **隐私默认保护**：本仓库是公开的；不得提交私人对话、未发表稿件、个人案例原文、密钥或私有恢复文件内容。

## 项目隔离

每一部新书独立建立 \`PROJECT_ID\`、独立恢复入口、独立版本/审稿/验收记录。优先**单独私有 GitHub 仓库**；在可证明私密的授权仓库中可使用独立目录。若连接缺乏私有仓库创建能力，不得悄悄在本公开仓库储存书稿；采用私有文件库保存实体和 SHA，并把 \`GITHUB_PRIVATE_REPO_PENDING\` 记为未关闭门。模板见 [PROJECT_INIT.md](PROJECT_INIT.md)。
