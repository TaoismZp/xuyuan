# DeepWrite v0.1｜工作台成品契约与质量门

状态：\`DESIGN_WITH_LOCAL_PACKAGER\`，不是无人值守一键写书产品。

## 不可混同的资产

\`CONCEPT_MAP\` 原始领域知识依赖；\`BOOK_BLUEPRINT\` 为特定读者设计的顺序；\`CHAPTER_CONTRACT\` 每章教会何种不可替代的决策；\`CHAPTER_DRAFT\` 完整正文（派生版本，不覆盖原稿）；\`AUDIT\` 绑定正文哈希与反例；\`SOURCE_LEDGER\` 事实数学与可核来源；\`PRIMARY_BOOK\` 序言+章节+尾声+附录的实际可读成品；\`RECOVERY\` 状态、版本、唯一下一步。

## 状态机

\`WISH→PROJECT_CREATED→SOURCE_INGEST→DOMAIN_MAP→BOOK_PLAN→TWO_CALIBRATION_CHAPTERS→CHAPTER_LOOP→CROSS_CHAPTER_AUDIT→FRONT_AND_BACK→PACKAGE→INDEPENDENT_ACCEPTANCE→CANDIDATE→AUTHOR_SIGNOFF\`。

任何 Gate 失败必须退回适当环节：\`RESEARCH_MORE / MERGE / REWRITE / STOP_WORK\`，不得通过继续堆章数规避。

## 八道质量门

|Gate|要交出什么|触发返工|
|---|---|---|
|G0 读者与成品|读者已有知识、未知知识、真正使用场景、成品和禁区|读者角色不清/自作主张|
|G1 原生知识|原生概念、决策树、反例、依赖|以目标领域结论反写原始概念|
|G2 代表样章|两种不同风格章节、正负质量基线|样章劣于基线仍批量生产|
|G3 一章一能力|本章独占判断问题、行动者、现金流/支付/约束|能平移到邻章而无损|
|G4 第二次发现|后半新机制、新变量、新后果、可反驳边界|只有前半的重述|
|G5 事实与公式|原始来源/时间/统计口径、复算、正文SHA绑定审稿|无法追溯或审稿对应旧稿|
|G6 整书连续性|重复/知识前置/标题与案例节奏/全书信息增量|每章单篇好看但整书同质|
|G7 交付身份|真实整书、序/尾/必要附录、来源表、独立验收状态、恢复点|大纲/报告充成作品|

内部审稿只可标\`PASS_INTERNAL\`；作者终审与独立人类盲评需独立证据，不能由同一个模型扮多个角色伪造。事实/隐私与法律边界随原任务评估。

## Clean Room 与跨章碰撞

先用当前材料与公共知识独立建立源领域可检验机制，**后**调用作者历史作品作查重、语气和约束匹配。移植到新领域需域内建立完整主体、价格、权利义务、可执行行为，禁止只替换术语。每章有 \`unique_capability\` 和 \`must_not_repeat\`；两章相同结果，执行\`MERGE/REWRITE/KEEP_DISTINCT\`。

## 交付循环与停止条件

每章内部研究→反方→结构→成稿→事实数学→老编辑→首次读者→返工；每3—5章跨章审；书成后全文检查与序言尾声。连续两章没有新增判断能力立刻 \`STOP_WORK\`，回知识地图。未见新题材A/B验证前不承诺首次就出出版级终稿。

## 机器与人类检查的边界

文件存在/SHA/顺序/公式/来源覆盖可工具验证；写作灵魂、反常识洞见、可读性及作者风格需实质对照，独立人类审稿仍为独立门。上级《许愿式交付》以 \`wish-delivery/CURRENT.json\` 生效版本为准。私有项目文稿严禁进入公开库。
