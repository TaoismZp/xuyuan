# DeepWrite v0.3.0｜统一默认写书工作台

**发布类型**：整合版正式执行入口候选。版本身份由 `main:deepwrite/CURRENT.json` 的 `active_engine` 和独立发布记录共同决定；文件在候选分支存在不等于正式发布。父协议为 `wish-delivery/CURRENT.json` 的实际生效版本。

## 用户合同

用户只需要说“调用 DeepWrite，写一本【主题】的书，源材料在【授权私有位置】，先写样章／一次授权整本候选”。系统自动选择现行功能；用户**不必**指定 E15、E18、E23、知识复利、章节数或每轮研究过程。

命令环境执行入口是 `deepwrite/deepwrite.py`；正式发布须由 `deepwrite/release/activation.py` 验证 `CURRENT` 与不可变 release record 后调用。普通聊天窗口若没有被授权的执行环境、模型凭证和私有项目文件访问，不能冒称已运行机器执行器。

## 默认研究与写作闭环

1. 恢复旧项目并核实际原稿SHA、RECOVERY/STATE和项目版本锁；新项目创建独立私有工作目录。
2. 冻结来源、授权范围和原始愿望。按照源学科本身研究基本机制、反常识理解、边界、竞争解释，区分作者明确提供视角与模型自行提出的问题。
3. **在源研究之后**，提出临时章数、章节顺序及读者概念依赖，拒绝机械照搬课程章目。
4. 在作者授权内通过 E18 实际生成原生概念学习、章节正文、三层读者审稿与跨情境知识复利探针；E15 对 MAJOR/CRITICAL 进行有证据返工与重新核验，审稿结果绑真实文件SHA。
5. 全书检查重复核心发现、重复案例、推理/数学矛盾、内容损失及逻辑依赖；必要时最多一次有依据的结构重编，保留旧书和全部源字节，另立派生稿进行整体重写。
6. 完整打包序、全章、尾及必要来源信息；保留原稿、返工记录、模组、模型成本、STATUS 与私有恢复点。
7. 可单独准备A/B隐匿版本的人类读者评价包，检查新手趣味与理解、熟手洞见、高手反证及陌生问题知识迁移。模型不可假装人类评分。

## 作者授权

- `ASSISTED_AUTHOR_GATED`：源研究之后确定动态首章，写样章后停止；只有独立于模型的精确稿件SHA外部批准才能续写。
- `AUTONOMOUS_FULL_DRAFT`：仅在真实明确项目级授权范围内内部逐章、返工与整书处理，产出**候选稿**，**不授权公开发表或模型自我终审**。

## 质量与版本身份不可混淆

- 工程CI、单元测试、真实模型输出、真人陌生读者测试、作者签收须分别记录。
- 工程fixture通过表示代码运行和负控已检查；不证明源研究原创、成稿文学性或黑箱整书质量不弱于逐章。
- 未经真实模型、独立读者和作者成稿验收，标 `E1/E2/QUALITY_UNVERIFIED`，绝不能冒充质量PASS。
- 私有稿件、敏感信息、未发表内容不进入本公开Git历史；旧项目保持原生效版本钉死，不强制迁移。
- 关键版本只能由 GitHub 正式发布流程更新main中的CURRENT；不得由 README、候选登记、聊天记忆自认生效。

## 可查阅入口

- `deepwrite/DEFAULT_INVOCATION.md`：自然语言用法与执行环境界限。
- `deepwrite/deepwrite.py`：一个命令编排动态研究、两种授权模式与 E18、整书重审。
- `deepwrite/AGENTS.md`：Codex/Work 代理处理 “调用 DeepWrite” 的入口。
- `deepwrite/UNIFIED_RELEASE_CANDIDATE.json`：功能与未关质量门真相（候选历史记录）。
- `deepwrite/release/RELEASE_PROCESS.md`：保护规则、身份、授权及回退。

## 验收线

发布生效至少需要：
- 确切 Git commit 与 SHA256 的正式release record，父协议身份和 main `CURRENT` 匹配，发布后从新拉取的工作树运行 resolver 与 `identity` 成功；
- GitHub 主线保护规则、CI、合并/所有者身份实测，保证规范要求的授权和发布控制；
- 认知质量变化所需真实新题材/完整书稿/比较/独立评审为 PASS，或者将其清楚留作正式发布的阻断，不因工程测试自动改为PASS。
