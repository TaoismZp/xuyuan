# DeepWrite 统一调用代理约定（适用于在此目录中工作的 Codex/Work）

当用户在新聊天、新任务或仓库内说“调用 DeepWrite”、“用 DeepWrite 写这本书”时：

1. **只解析一个正式有效入口**：先读取 `main:deepwrite/CURRENT.json` 与 `wish-delivery/CURRENT.json`；若 `active_engine` 为 `deepwrite/deepwrite.py`，在合法执行环境用 `deepwrite/release/activation.py --run` 严格校验并启动。不得从未合并 PR 或聊天的“最新版本”推测已发布。
2. 任何完成调用都默认执行 `deepwrite/DEFAULT_INVOCATION.md` 所述适用链：恢复、来源独立研究、竞争性洞见生成/作者来源归因、研究后决定章序、三层读者和知识复利、新情境迁移审查、E18真实章节写作与E15强制改稿、跨章/整书返工、原稿保留与私有检查点回读。**绝不要求用户知道或自己挑 E15/E18/E23/PR17/PR18/PR19。**
3. 只问确实缺少的最关键作者决定，例如全书候选还是样章先审；已有用户明确授权的范围不得重复询问。显式授权不仅是参数，还须保留原始请求SHA。正式作者签收、公开发布、付款及真人读者评价不能自动代替本人决定。
4. 没有真实provider凭据、Git、私有存储、有效源文件时明确 BLOCKED，并提供源文件、恢复入口和唯一下一步；不能伪称已经调用引擎、不用“先给大纲”冒充完整写书。
5. 已归档旧项目必须先核对私有 `RECOVERY.md` / `STATE.json`，保持锁定的作者原稿及已生效版本。新试验使用独立私有工作目录和新项目标识，不向公开仓库泄露私人文稿。
6. 若 `CURRENT` 仍为 v0.1／无正式 `active_engine`，**不能回答“现在直接说调用DeepWrite已经默认调用所有新功能”**；只允许在用户明确授权的候选测试下运行合并候选，且说明当前正式发布门未通过。工程fixture PASS、书稿数学自检、作者认可、真人阅读收益是四种不同状态。
7. 对未知源领域不要机械复制先前《孙子兵法》或《NO FOLD》章节图/视角；不得因过去得到高分就形成新路径依赖。三层读者与王路知识复利是一个贯穿全书的质量目标，不是固定六点、三段评分模板。

所有具体调用命令、受控默认范围和历史功能状态见 `DEFAULT_INVOCATION.md`、`UNIFIED_RELEASE_CANDIDATE.json`。本文件在未合并分支上只是候选操作契约，不是 ChatGPT 产品已内置的可执行插件。
