# DeepWrite 数据分级与长期保存

**当前仓库 \`TaoismZp/xuyuan\` 是公开的。所有人都能看到本目录及Git历史。**

## 三类数据

- PUBLIC：无私人内容的工作台方法、通用工具、匿名化失败复盘、空白模板、公开测试代码。允许进入此仓。
- PRIVATE_PROJECT：作者未发表稿、原始素材、章节候选、批注、审稿证据、具体个人工作记录。应保存在单独的**私有**项目仓库或私人文件库，权限经过核验才能写入。仓库名、文件名本身也可能泄露未发表计划，应谨慎。
- SECRET：令牌、密码、个人联系人、凭证、未授权完整对话导出，禁止上传GitHub。

## 建仓规则

优先每新项目单独私有仓库。若GitHub连接不能创建仓库：不得“临时”用公开 \`deepwrite/projects/\` 代替保存 PRIVATE_PROJECT；先在私有文件库存真实产物与RECOVERY，同时将 \`GITHUB_PRIVATE_REPO_PENDING\` 明确登记。用户创建/授权仓库后再迁移，上传后按SHA回读。公共仓库只放通用空模板。

既有 \`ai-context\` 私有仓库有自己的白名单与禁止未发表手稿的约束，不得擅自把它当完整写书档案仓。

## 不丢失的实际边界

Git历史有提交版本和哈希，便于审核回滚；但误删、泄露权限、令牌问题或平台故障不能承诺绝对不会发生。GitHub不是ChatGPT对话的自动备份器。对重要内容推荐独立私有备份、导出归档、异地副本、恢复抽检。删除Git当前文件不等于删除历史敏感内容。

每次写入：计算源文件 SHA256 → Git commit → 重新fetch验证内容/路径/版本 → 更新独立RECOVERY和唯一下一步；只在真实可查时写 PASS。旧版本不覆盖，隐私权限每个新项目重新核验。
